# Route Progress for Home Assistant v0.15.1

## Fix

The destination preview could show map tiles without a target marker. Modern Home Assistant map components read entity coordinates from the `states` context, while the preview previously supplied its temporary target only through the outer card's `hass` property. The map subtree now receives the same preview state through both interfaces. No real HA entity or saved destination is changed by opening a preview, and no additional geocoding calls are needed.

## Upgrade

The repository now publishes a full HACS-compatible GitHub release automatically on pushes to `main` when the manifest contains a new version and release notes exist. Publication is gated by unit tests, HACS and Hassfest. Existing release versions are never overwritten.

Install the integration update, restart Home Assistant and reload the dashboard/Companion App. The bundled card resource version is updated to invalidate the previous frontend cache. Existing configuration and selected destinations are preserved. No server update is required.

## Validation

The browser regression test now includes a nested map component consuming state through the bubbling Lit context protocol. It checks target coordinates, the marker label, reopening the preview and propagation of unrelated HA contexts. This uses simulated HA components; a live HA installation was not available for verification.
