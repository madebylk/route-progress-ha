# Route Progress for Home Assistant v0.14.0

Share trips without vehicle navigation entities: choose a destination from Geoapify search, a Google Maps place link, or a Home Assistant zone, and use a vehicle or smartphone for position updates.

## New

- Freely placeable **Route Progress dashboard card** with destination search, Google Maps link input, HA zones, map preview, trip controls, and share-link copying/sharing. Add it through **Edit dashboard → Add card → Route Progress**, or use `type: custom:route-progress-card`.
- Two-step setup and reconfiguration with a choice between **Automatically from entities** and **Manual: search, Maps link or HA zone**.
- The optional Geoapify API-key field appears only in manual mode. Home Assistant calls Geoapify and resolves supported Google Maps short links directly; keys and search queries are not sent to the Route Progress server.
- Manual destinations survive restarts. Changing an active trip's destination requires explicit confirmation in the card. Provider attribution is preserved with saved destinations.
- German and English interface text and a Best Practices guide in the README.

## Updating an existing installation

- Existing configurations default to the previous entity mode. Server credentials, selected entities and update intervals are retained; no reconfiguration or Geoapify key is required.
- To use manual selection, finish any active share, choose **Reconfigure**, switch the destination source, and optionally enter a Geoapify key. Switching sources during an active share is blocked.
- Refresh the dashboard or Companion App after the integration update if the card is not yet listed. The integration registers the frontend resource automatically; no separate HACS card installation is required.
- Multiple cards control the same integration and journey. Home Assistant entity permissions apply.
- Update the Route Progress server to **v0.13.0 or newer** to obtain estimated ETA and remaining distance when those vehicle metrics are absent. The integration still works with older compatible servers, but those estimates may remain unavailable.

## Scope and privacy

- Address searches require a Geoapify key. HA zones and supported links with explicit destination coordinates work without one. Free-tier quotas are governed by Geoapify's current plan.
- Maps links must resolve to a single identifiable target. Ambiguous directions/multi-stop links, viewport-only links, and opaque unsupported place identifiers are rejected rather than guessed.
- Selecting a destination alone does not create a public share. A new journey still uses the server's normal destination-confirmation process.
- Search text goes to Geoapify, short-link resolution contacts Google, and the map preview contacts OpenStreetMap. Credentials remain in the HA config entry.
- Smartphone background-location permissions and GPS freshness still determine update frequency.

## Validation

42 Python tests cover lookup responses, link validation, configuration branching, permissions, restart persistence and existing snapshot behavior. The card passed a browser smoke test with a simulated Home Assistant connection. A live HA upgrade and real-key Geoapify request have not been exercised locally; the release workflow additionally runs HACS and Hassfest validation.
