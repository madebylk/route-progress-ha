# Route Progress for Home Assistant v0.15.0

## Geoapify validation and diagnostics

- Manual-mode setup and reconfiguration validate the supplied Geoapify key before saving. Invalid keys, quota limits and connection failures appear directly on the field; the existing configuration is retained on failure.
- A Geoapify connection diagnostic sensor appears beside Cloud connection when a manual-mode API key is configured. It reports the last observed provider result, last check, last success and a safe error code independently of the Route Progress server.
- Successful validation is reused for 15 minutes, failed validation for one minute. Setup and runtime share results to avoid duplicate checks; actual searches update the diagnostic without extra requests.
- No periodic health polling. After a full HA restart, one initial check establishes status. Invalid-key/quota responses suppress further provider requests for one minute. Zones and coordinate-only Maps links remain usable without a search request.

## Upgrade

Existing source settings and credentials are retained. Install the integration update, restart Home Assistant, and find the new entity under the Route Progress device's diagnostics. No server update is required. Without a Geoapify key or in entity mode, no new provider calls are made. A connection state is the last known observation, not continuous monitoring.

The README now includes detailed HACS dashboard-card installation, configuration, controls and troubleshooting instructions.

## Validation

Python tests cover cached validation, error mapping, key isolation, recovery, diagnostic state and the existing destination workflow. Tests use simulated HTTP and Home Assistant boundaries; live Geoapify credentials and a running HA installation have not been used for these checks.
