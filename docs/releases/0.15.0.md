# Route Progress for Home Assistant v0.15.0

## Geoapify validation and diagnostics

- Manual-mode setup and reconfiguration validate the supplied Geoapify key before saving. Invalid keys, quota limits and connection failures appear directly on the field; the existing configuration is retained on failure.
- A Geoapify connection diagnostic sensor appears beside Cloud connection when a manual-mode API key is configured. It reports the last observed provider result, last check, last success and a safe error code independently of the Route Progress server.
- Successful validation is reused for 15 minutes, failed validation for one minute. Setup and runtime share results to avoid duplicate checks; actual searches update the diagnostic without extra requests.
- No periodic health polling. After a full HA restart, one initial check establishes status. Invalid-key/quota responses suppress further provider requests for one minute. Zones and coordinate-only Maps links remain usable without a search request.

## Compact card and native entities

- More compact HA typography and spacing; redundant heading/help removed. Search results collapse into a clearly labelled pending selection with the full address.
- Optional native HA map preview replaces the external iframe. An external map link remains available if preview loading fails.
- Manual mode exposes a text input, search-result selector, zone selector and selected-destination sensor for normal HA dashboards and automations.
- A manually chosen destination can be confirmed immediately by the updated server; GPS timestamps are not fabricated and automatic entity mode retains its stabilization period.

## Upgrade

Existing source settings and credentials are retained. Install the integration update, restart Home Assistant, and find the new entity under the Route Progress device's diagnostics. Card and entity improvements work with existing servers. Immediate confirmation of manual targets requires server v0.14.0 or later; older servers keep their existing confirmation period. After upgrading an older server, reload the integration. Without a Geoapify key or in entity mode, no new provider calls are made. A connection state is the last known observation, not continuous monitoring.

The README now includes detailed HACS dashboard-card installation, configuration, controls and troubleshooting instructions.

## Validation

59 Python tests cover cached validation, error mapping, key isolation, recovery, diagnostic state, native destination entities and manual initial confirmation. Browser tests exercise the actual card, collapsed results, map helper/fallback, selection, sharing, stale responses and layouts at 320/420/800 pixels; light and dark previews were inspected. HA and map components use boundary doubles; live Geoapify credentials and a running HA installation have not been used for these checks.
